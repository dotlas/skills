# Slack

Two jobs, one standard: respect the reader’s time.

- **Compose** — write a message for a thread or channel.
- **Digest** — turn a thread into a short briefing.

Avoid sending DMs if the context was already set using a conversation thread.
Hence, further messages should only go to the thread.

## How to write

Every line earns its place.
Most first drafts lose half their words without losing a fact — do that cutting
yourself, not by handing off to another skill.

- **Lead with the takeaway.** First line is the point, not a windup.
- **Facts only.** What happened, what changed, what it means.
  No unsolicited recommendations or “let me know if…” filler.
- **Don’t repeat what the reader already knows.** If the thread or context establishes
  it, cut it.
- **Plain, not dumbed-down.** Write for the least-technical likely reader.
  No internal or metaphorical jargon ("boil the ocean", “move the needle”) — if the
  reader can’t decode a word cold, cut it or replace it in the same sentence.
  One idea per sentence.
  Name a term only if it earns its place, and define it plainly when you do.
- **Keep it short.** No emojis.
  A table only when it genuinely reduces effort (comparing options, tracking items).
- **Link sparingly.** Add a link only when it saves the reader a hunt and they can open
  it. Inline it on the words it describes.
  No link piles, no “References” sections.

## Compose

A reply is a lead line plus a few tight bullets, not an essay.

Before writing, know why the message exists — to answer a question, unblock a decision,
report a result, correct a misread.
The message must answer what was actually said and fit sensibly at this point in the
conversation. If it has no clear job, don’t send it.

**If you are sending a slack message that requires more than 10 sentences, or exceeds
200-250 words, re-consider the distillation and try to compact further**.

## Digest

Return a layered briefing, not the transcript:

- One line: what the thread is about and where it stands (open / decided / blocked).
- A few bullets: decisions, the open question, who owns what — only what bears on the
  reader’s task.
- A table only when comparing options or tracking items.

Quote a line verbatim only when exact wording matters (a decision, a number, an error).
Offer to go deeper rather than front-loading everything.
